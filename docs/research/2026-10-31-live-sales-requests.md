# Live-sales requests in the dashboard

Products takes a new merchant straight to the integration choice. Seller
name stays editable in Settings and is also asked at the step where it is
needed: a live-sales request, or the test channel's first publication.

A live merchant can ask after their code connects or a current shop check
finds a ready product. The request needs a seller name and no payout wallet.
It retains its date and integration evidence while waiting, including when
the merchant's code goes quiet. A later request replaces the previous decision
on Products. A declined request and a standing withdrawal show the full
operator note and let the merchant ask again.

The operator's Needs you list contains pending requests, oldest first, and
shows whether a wallet is missing. The merchant page shows the request's date
and integration evidence beside the current seller name and wallet. Declining
requires a note, a fresh operator sign-in, a checked consequence and the exact
request the page showed. A stale form cannot decline a newer request.

Request, decline and reminder mail use the durable backend delivery owner.
This slice does not publish shop products automatically at admission or send
an approval result email. Those belong to the next slice. Its interim wallet
copy therefore promises only that the merchant can save a wallet while
waiting.

The test channel saves seller name and wallet in one form. A shop then offers
publication of its checked products; connected code offers the publishing
guide. Partial saves distinguish the saved name from an unconfirmed wallet.
Coinbase uses the existing driver; it fills the box and the merchant saves it.
New commerce-v1 instrumentation belongs to slice 8.
